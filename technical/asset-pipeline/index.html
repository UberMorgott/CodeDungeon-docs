    Конвейер 3D-ассетов¶

    Этот документ задаёт целевую инженерную границу подготовки визуальных 3D-ассетов для Godot. Внешний генератор или художник создаёт сырьё; внутренний pipeline превращает его в валидируемый ресурс CodeDungeon. Runtime не исправляет несовместимые ассеты на лету.

    Статус¶

    Принято как направление: внутренний формат и проверки проекта не зависят от конкретного AI-сервиса; персонажи и экипировка используют ограниченный набор канонических тел/скелетов; оружие является отдельным ресурсом с sockets и metadata.

    Не внедрено и требует прототипа: автоматические remesh/UV/rig, перенос весов, fitting брони, clipping auto-fix, генерация collision/LOD и полный asset compiler. Название CodeDungeon Asset Compiler обозначает границу системы, а не существующий продукт.

    Граница ответственности¶

    Pipeline владеет:

    • импортом исходного mesh/texture/rig и provenance metadata;
    • нормализацией масштаба, осей, origin и имён;
    • преобразованием к каноническому skeleton/profile;
    • sockets, collision shapes, LOD и runtime metadata;
    • автоматическими проверками и воспроизводимым отчётом;
    • публикацией только прошедшей проверки версии ассета.

    Pipeline не владеет gameplay stats предмета, формулами урона, балансом, выбором атаки или runtime-физическим исходом. Gameplay definition ссылается на опубликованный visual asset по stable ID; visual metadata не становится скрытым вторым источником gameplay-чисел.

    Целевой поток¶

    Authored / scanned / AI-generated source
                │
                ▼
        source + provenance
                │
                ▼
     geometry/texture preparation
     remesh · UV · material cleanup
                │
                ▼
      canonicalization stage
     scale · axes · origin · naming
     skeleton · fitting · weights
                │
                ▼
        runtime enrichment
     sockets · collisions · LOD
     body masks · asset metadata
                │
                ▼
          validation suite
     pose stress · clipping · bounds
     topology · dependencies · budget
                │
                ▼
       PASS / review / regenerate
                │
                ▼
       versioned GLB + Godot import

    Каждый автоматический шаг должен быть идемпотентным либо фиксировать tool/version/parameters, чтобы результат можно было воспроизвести. Ручное исправление сохраняется как новый source или явный patch stage, а не как неотслеживаемая правка результата сборки.

    Входы и provenance¶

    Источником может быть ручная работа, maintained tool или внешний text/image-to-3D сервис. Meshy, Tripo и Hunyuan3D являются примерами кандидатов, не принятыми зависимостями.

    До попадания source в проект необходимо сохранить:

    • автора/сервис и дату получения;
    • prompt/reference IDs там, где это допустимо;
    • лицензию и разрешённые способы использования/переработки;
    • версию генератора и существенные параметры;
    • hashes входов и исходного результата;
    • отметку human review.

    Ассет без достаточного provenance не публикуется. Внешний сервис не определяет внутренний skeleton, axes, размеры, material contract или naming.

    Канонические тела и скелеты¶

    Проект использует небольшой versioned registry body profiles и skeleton contracts вместо уникального несовместимого rig для каждого результата генерации. Конкретное количество мужских/женских форм из исходной концепции не утверждено.

    Skeleton contract должен определить:

    • stable bone names и hierarchy;
    • bind pose, orientation и единицы масштаба;
    • обязательные/необязательные bones;
    • sockets оружия, щита, спины, бедра и колчана;
    • связь с hit zones и physical-bone profile без дублирования gameplay-схемы;
    • правила совместимости и миграции версии.

    Изменение skeleton contract требует version bump, миграционного отчёта и regression-набора анимаций/экипировки.

    Броня и одежда¶

    Предлагаемый поток: normalize → fit к body profile → transfer/author skin weights → pose stress test → clipping validation → review. Автоматический auto-fix допускается только как диагностируемый этап с порогом уверенности.

    Для полностью закрытых участков может применяться явная body mask metadata. Она принадлежит visual asset и не меняет gameplay coverage брони. Плащи, юбки, ремни и подвесы могут использовать дополнительные bones или secondary motion после отдельного performance-теста.

    Validation poses должны покрывать не только idle, но и крайние положения оружия, locomotion, падение и recovery. Допуски clipping задаются для body profile и категории предмета.

    Оружие и sockets¶

    Оружие не встраивается в mesh тела. Опубликованный ресурс содержит visual mesh, локальную систему координат, grip points и совместимость с socket contract.

    Кандидат минимальной metadata-схемы:

    asset_id: weapon.longsword.example
asset_schema: 1
category: two_handed_sword
primary_grip: [0.0, 0.13, -0.02]
secondary_grip: [0.0, 0.52, -0.02]
forward_axis: [0, 0, -1]
edge_axis: [1, 0, 0]

    Это visual/attachment metadata. Авторитетные mass, damage tags, requirements и balance values принадлежат content package. Если collision geometry выводится из asset, она проходит отдельную проверку и публикуется как versioned runtime artifact.

    Валидация и бюджеты¶

    Публикация должна отклонять либо отправлять на review ассеты с:

    • неверным масштабом, axes, origin или bounds;
    • отсутствующими обязательными bones/sockets/material slots;
    • invalid topology, missing dependencies или несовместимой schema;
    • превышением polygon, texture, material, bone или draw-call budgets;
    • clipping выше допуска в обязательных poses;
    • недопустимыми collision shapes или LOD transitions;
    • отсутствующим provenance/license record.

    Числовые budgets определяются после целевой сцены из визуального направления. Проверки запускаются в CI без GUI; импорт Godot и representative scene smoke test входят в acceptance pipeline.

    MVP pipeline¶

    Первый срез ограничен одним humanoid skeleton, одним body profile, одним комплектом брони и двумя видами оружия. Он должен доказать:

    1. воспроизводимую сборку одного source в versioned GLB/Godot artifact;
    2. стабильные scale/origin/axes и sockets;
    3. retarget одной representative animation library;
    4. автоматический pose/clipping/budget report;
    5. отказ сборки при повреждённой metadata или неизвестной версии skeleton;
    6. документированный ручной fallback для шагов, которые пока нельзя надёжно автоматизировать;
    7. сохранение provenance и лицензии рядом с опубликованной версией.

    До прохождения этого среза массовая AI-генерация, автоматический armor auto-fix и обещание «никто не моделирует вручную» считаются недоказанными гипотезами.
