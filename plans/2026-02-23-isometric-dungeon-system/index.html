    Isometric Dungeon System Design¶

    Overview¶

    Transition the game from flat 2D to 2.5D isometric view (like PoE/Diablo) with a procedural dungeon floor system featuring multiple room types and player-driven navigation.

    Decisions¶

    Aspect Choice
    View 2.5D isometry (Node2D + Y-sort)
    Visual style Placeholders for now
    Floor map Procedural graph (PoE Atlas / Slay the Spire style)
    Room simulation Each room simulated individually (batch, same as current)
    Room types Combat, Elite, Treasure, Shop, Boss
    Navigation Player chooses next room on map

    Part 1: Isometric Coordinate System¶

    Server continues working in cartesian coordinates (x, y) — simpler for AI, physics, distances. Client transforms to isometric for display only:

    # Server coordinates (cartesian) → screen (isometric)
screen_x = (cart_x - cart_y) * 0.5
screen_y = (cart_x + cart_y) * 0.25

    Camera follows the player. Y-sorting determines depth — closer to "camera" draws on top. Room size on server expands (e.g., 1200x1000 instead of 800x600) — more space for AI tactics.

    Part 2: Floor Map¶

    Procedural graph generated by server at run start:

    START → [Combat] → [Combat] ─→ [Elite] ──→ [Combat] → [BOSS]
                  ↘ [Treasure] ↗        ↘ [Shop] ↗

    Graph structure: - Layers: 5-8 layers between START and BOSS - Each layer: 1-3 nodes (rooms) - Edges connect only adjacent layers (forward only, no backtracking) - Seed-based — one seed = same floor

    Room type distribution: - Layer 1: always Combat (soft start) - Middle layers: Combat 50%, Elite 15%, Treasure 15%, Shop 20% - Last layer: always Boss - Guarantee: minimum 1 Shop and 1 Treasure per floor

    Protocol: server sends full graph to client (nodes + edges + types), client renders map. After clearing a room — player clicks available next room, server simulates it.

    Part 3: Room Structure¶

    Each room is a rectangular area with parameters:

    Sizes (server, cartesian): - Combat: 1200×1000 - Elite: 1400×1200 - Boss: 1600×1400 - Treasure/Shop: 800×800

    Room contents: - Floor — client draws with iso-tiles (placeholders: gray diamonds) - Walls — room boundary, server enforces bounds - Doors — entry/exit points, visually marked on client - Obstacles — pillars/pits for AI tactics (future, not MVP)

    Spawning: - Player spawns at entry door - Enemies spawn in far part of room - Treasure: chest in center, no enemies - Shop: NPC merchant, no enemies

    Non-combat rooms (Treasure, Shop): - Not batch-simulated — result is instant - Treasure: server generates loot, sends to client → selection screen - Shop: server sends inventory → client shows purchase UI

    Combat rooms (Combat, Elite, Boss) — batch simulation as current, but with expanded space and camera following player.

    Part 4: Client Architecture¶

    New screens in UIManager:

    MainMenu → Profile → [Solo starts run]
                          ↓
                     FloorMap (floor map — room graph)
                          ↓ (click on room)
                     GameView (combat — isometric, playback)
                          ↓ (victory)
                     RoomResult (loot, stats)
                          ↓
                     FloorMap (choose next)
                          ...
                     BossDefeated → NextFloor / Victory

    Treasure/Shop — separate screens (no simulation): - TreasureScreen — shows 2-3 items, player picks - ShopScreen — item list with prices, purchase

    Isometric renderer (GameView rework): - World Node2D with y_sort_enabled = true - Camera (Camera2D) follows player: smooth movement to player position each tick - Floor: drawn as diamond grid via script or TileMapLayer (iso mode) - Entities: same character.tscn, but position via iso_transform(server_x, server_y) - Walls/doors: placeholder sprites along perimeter

    New protocol (additions to game.proto): - FloorMap — room graph (nodes, edges, types) - SelectRoom — client → server: selected room - RoomReward — loot after combat - ShopInventory / ShopBuy — items and purchase

    Part 5: Server Architecture¶

    New packages in server/internal/:

    internal/
├── dungeon/          — NEW
│   ├── generator.go  — procedural graph (seed-based)
│   ├── floor.go      — Floor struct (graph + progress state)
│   └── templates.go  — room templates (sizes, spawns by type)
├── loot/             — NEW
│   ├── loot.go       — reward generation by room type/level
│   └── shop.go       — shop inventory generation
├── room/
│   └── room.go       — extend: stores room type, size, doors
├── game/
│   ├── handler.go    — new opcodes: SelectRoom, ShopBuy
│   └── simulator.go  — walls as boundaries, spawn by template
└── ai/               — no changes (for now)

    Run lifecycle: 1. Player clicks Solo → server creates Run (seed, floor=1) 2. Server generates Floor (room graph) → sends FloorMap 3. Player selects room → SelectRoom 4. Combat/Elite/Boss: server simulates → SimulationResult + RoomReward 5. Treasure: server generates loot → RoomReward (no simulation) 6. Shop: server sends ShopInventory → waits for ShopBuy 7. All paths lead to Boss → victory → floor++ → new FloorMap

    Run state stored in server memory: current floor, cleared rooms, inventory, HP between rooms (persistent HP — damage carries over).

    Part 6: Implementation Order¶

    Split into 3 sub-phases — each delivers a working result:

    Sub-phase A: Isometric (visual)¶

    1. Iso-transform on client (iso_transform function)
    2. Y-sort in World node
    3. Camera follows player
    4. Floor from diamond placeholders
    5. Wall placeholders along perimeter
    6. Increase room size on server (1200×1000)

    Result: current single room, but looks isometric.

    Sub-phase B: Floor map + navigation¶

    1. Proto: FloorMap, SelectRoom, RoomReward, new opcodes
    2. Server: dungeon generator (graph), floor state, run state
    3. Server: handler processes SelectRoom → simulates → sends result
    4. Client: FloorMap screen (graph visual, click on room)
    5. Client: RoomResult screen (loot after combat)
    6. Client: flow — FloorMap → GameView → RoomResult → FloorMap

    Result: full run through multiple combat rooms to boss.

    Sub-phase C: Treasure + Shop¶

    1. Proto: ShopInventory, ShopBuy
    2. Server: loot generator, shop generator
    3. Client: TreasureScreen, ShopScreen
    4. Persistent HP between rooms
    5. Inventory (minimal — store collected items)

    Result: complete run with all room types.
