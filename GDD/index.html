    Game Design Document — CodeDungeon¶

    Рабочее название. Roguelite где ты не играешь за персонажа — ты программируешь его.

    1. Core Concept¶

    Жанр: Top-down 2D multiplayer co-op roguelite с AI-программированием

    Elevator pitch: Вместо того чтобы управлять персонажем напрямую, игрок программирует его поведение через визуальные блюпринты. Персонаж сражается автономно, а игрок наблюдает — как его "код" справляется с подземельями. Между забегами игрок разбирает лут, вставляет скиллы в сокеты, пишет новые блюпринты и оптимизирует AI под ограниченную память.

    Ключевое отличие: Удовольствие не от рефлексов, а от того что твой "код" работает. Ты архитектор, а не пилот.

    Режим наблюдения: Во время боя игрок только смотрит. Никаких кнопок, микрокоманд или ультимейтов. Чистая автономия AI. Если персонаж делает глупость — это баг в твоём блюпринте, иди чини.

    2. Core Loop¶

    ┌─────────────────────────────────────────────────────┐
│                      БАЗА                           │
│  Разбор лута → Вставка скиллов в сокеты →           │
│  Написание/правка блюпринтов → Распределение памяти │
│  → Мета-прогрессия (новые ноды, сокеты, модули)     │
└───────────────────────┬─────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│                     ЗАБЕГ                            │
│  Вход в подземелье → Комната 1 (бой, авто) →        │
│  Лут падает в сумку → Комната 2 → ... →             │
│  Босс → Конец забега → Возврат на базу              │
└─────────────────────────────────────────────────────┘

    Между комнатами: Никакого редактирования. Лут копится, AI работает как есть.

    На базе (между забегами): - Разбор инвентаря (скиллы, саппорты, экипировка) - Вставка скиллов в сокет-ноды - Редактирование блюпринтов AI - Распределение памяти между модулями - Трата мета-валюты на прогрессию

    3. Blueprint System (AI Programming)¶

    Концепция¶

    Блюпринты — визуальный язык программирования поведения персонажа. Игрок строит графы из нод (условия, действия, приоритеты), определяющие что персонаж делает в каждой ситуации.

    Типы нод¶

    Условия (Conditions): - HP Below % — проверка здоровья (своего или цели) - Enemy In Range — враг в радиусе (ближний/дальний) - Ally HP Below % — здоровье союзника - Skill Ready — скилл снят с кулдауна - Enemy Count — количество врагов в радиусе - Has Tag — проверка тегов на цели (boss, elite, ranged) - Module Active — проверка текущего активного модуля

    Действия (Actions): - Use Skill [name/tag] — использовать скилл по имени или тегу - Move To [target] — двигаться к цели (enemy, ally, cover, away) - Move Away From [target] — отступить - Take Cover — найти и занять укрытие - Wait [seconds] — ждать

    Управление потоком (Flow Control): - Priority Selector — выполняет первый подходящий дочерний нод - Sequence — выполняет все дочерние по порядку - Loop — повторяет блок - Random — случайный выбор из дочерних нод

    Таргетинг (Targeting): - Nearest Enemy — ближайший враг - Lowest HP Enemy — самый раненый враг - Lowest HP Ally — самый раненый союзник - Highest Threat — враг наносящий больше всего урона - By Tag [tag] — цель с определённым тегом

    Обращение к скиллам¶

    Скиллы указываются по имени или тегу: - Use Skill "Fireball" — конкретный скилл - Use Skill [tag:heal] — любой скилл с тегом heal - Use Skill [tag:aoe, tag:damage] — AoE + урон

    Если скилл вставлен в сокет, но нигде не используется в блюпринте — игрок получает warning (не ошибку). Скилл просто не будет применяться.

    Пример блюпринта "Aggressive Melee"¶

    Priority Selector
├── [HP Below 20%] → Use Skill [tag:heal] → Move Away From [Nearest Enemy]
├── [Enemy In Range 2m] → Use Skill [tag:melee] → Sequence:
│   ├── Use Skill "Slash"
│   └── Use Skill "Kick" (if ready)
├── [Enemy Count > 3, In Range 5m] → Use Skill [tag:aoe]
└── [Default] → Move To [Nearest Enemy]

    Complexity Curve¶

    Meta Level Доступные ноды Пример
    1 (старт) 5 базовых HP check, Use Skill, Move To, Nearest Enemy, Priority Selector
    5 +5 средних Enemy Count, Ally HP, Sequence, Take Cover, Lowest HP
    10 +5 продвинутых Loop, Random, Has Tag, Highest Threat, Module Active
    15 +5 экспертных Custom variables, Cooldown tracking, Combo chains, Conditional tags
    20+ Полный набор Всё открыто, дальше — расширение памяти и сокетов

    4. Memory System¶

    Концепция¶

    Память — единый ограниченный ресурс, аналог RAM. Каждый нод в блюпринте, каждый модуль, каждое условие стоит определённое количество единиц памяти. Если память кончилась — нельзя добавить новые ноды. Нужно оптимизировать или расширить через мета-прогрессию.

    Глобальная vs Локальная¶

    Тип Аналогия Описание
    Глобальная ~/.claude/CLAUDE.md Базовое поведение, работает ВСЕГДА: уворот от снарядов, подбор HP, базовое позиционирование
    Локальная (по модулям) project/CLAUDE.md Специфичное поведение модуля: атака, лечение, танкование

    Общий пул памяти делится между: - Глобальным AI (всегда активен) - Модулями (каждый жрёт свою долю)

    Распределение — выбор игрока. Мощный глобальный AI = меньше памяти на модули. Много модулей = каждый тупее.

    Стоимость нод (примеры)¶

    Нод Стоимость памяти
    HP Below % 1
    Move To 1
    Use Skill 2
    Priority Selector 2
    Sequence 1
    Enemy Count 2
    Has Tag 2
    Loop 3
    Custom Variable 4
    Combo Chain 5

    Начальная память и рост¶

    Meta Level Общая память Рекомендуемое разделение
    1 20 8 global + 12 на 1 модуль
    5 35 10 global + 25 на 2 модуля
    10 55 15 global + 40 на 3 модуля
    20 100 20 global + 80 на 4-5 модулей

    5. Modules (Behavioral Modes)¶

    Концепция¶

    Модули — именованные блоки поведения, которые активируются автоматически по условиям. Аналог функций/классов в программировании. Каждый модуль содержит свой блюпринт и стоит отдельную память.

    Структура¶

    Персонаж
├── Глобальный AI (всегда активен)
│   ├── Dodge projectiles
│   ├── Pick up health if HP < 50%
│   └── Basic positioning
├── Module: "Aggressor" (condition: enemies > 0)
│   └── [Attack blueprint...]
├── Module: "Healer" (condition: ally HP < 40%)
│   └── [Healing blueprint...]
└── Module: "Survivor" (condition: own HP < 25%)
    └── [Defensive blueprint...]

    Приоритет модулей¶

    Модули имеют числовой приоритет (1 = высший). Если несколько условий true одновременно — активируется модуль с наивысшим приоритетом. Глобальный AI работает ПОВЕРХ любого модуля (всегда).

    Условия активации модуля¶

    Каждый модуль имеет условие включения — по сути мини-блюпринт из 1-3 нод условий: - Own HP Below 25% → Survivor mode - Ally HP Below 40% → Healer mode - Enemy Count > 0 → Aggressor mode - Boss Present → Boss Fight mode - Default → Idle mode

    Условие активации модуля тоже стоит память (из пула того модуля).

    Мета-прогрессия модулей¶

    Meta Level Слоты модулей
    1 1 модуль
    5 2 модуля
    10 3 модуля
    15 4 модуля
    20 5 модулей

    6. Skill Socket System¶

    Концепция (PoE-style)¶

    Скиллы вставляются в сокеты. К скиллам подключаются саппорты, модифицирующие поведение. Скиллы имеют теги для обращения из блюпринтов.

    Типы сокетов¶

    Тип Цвет Описание
    Active Красный Атакующие скиллы (Slash, Fireball, Arrow)
    Support Синий Модификаторы скиллов (AoE, Lifesteal, Crit Chance)
    Utility Зелёный Утилиты (Heal, Shield, Dash)
    Passive Жёлтый Постоянные бонусы (не в блюпринтах, работают автоматически)

    Связи (Links)¶

    Саппорты подключаются к активным скиллам через связи (links):

    [Fireball] ──── [AoE Support] ──── [Burn Support]
    │
    └── Теги: damage, fire, aoe, ranged

    Результат: Fireball с увеличенной AoE зоной и эффектом горения.

    Теги скиллов¶

    Каждый скилл имеет набор тегов: - Тип урона: physical, fire, ice, lightning, poison - Дальность: melee, ranged - Эффект: damage, heal, buff, debuff, crowd-control - Область: single-target, aoe, cone, line

    Блюпринты обращаются к скиллам по тегам: Use Skill [tag:heal, tag:aoe] → используй любой AoE хил.

    Мета-прогрессия сокетов¶

    Meta Level Active сокеты Support сокеты Utility сокеты Passive слоты
    1 2 1 1 1
    5 3 2 2 2
    10 4 4 3 3
    15 5 5 4 4
    20 6 6 5 5

    7. Meta-Progression¶

    Мета-валюта¶

    Code Fragments — основная мета-валюта. Выпадает из врагов и боссов, сохраняется между забегами.

    Дерево прогрессии¶

    Meta Tree
├── AI Nodes (новые ноды для блюпринтов)
│   ├── Tier 1: Basic (HP Check, Move, Use Skill, Priority)
│   ├── Tier 2: Tactical (Cover, Ally HP, Enemy Count)
│   ├── Tier 3: Advanced (Loop, Random, Has Tag)
│   └── Tier 4: Expert (Variables, Combos, Conditional Tags)
├── Memory (расширение RAM)
│   ├── +5 memory per upgrade
│   └── Upgrades get progressively more expensive
├── Module Slots (новые слоты модулей)
│   └── Each slot costs significantly more than previous
├── Skill Sockets (новые сокеты)
│   ├── Active socket slots
│   ├── Support socket slots
│   ├── Utility socket slots
│   └── Passive slots
└── Quality of Life
    ├── Blueprint templates (pre-made module templates)
    ├── Auto-loot filters
    └── Replay speed options

    Прогрессия НЕ даёт прямую силу¶

    Мета НЕ увеличивает урон, HP или статы. Мета даёт инструменты: больше нод, больше памяти, больше скилл-слотов. Сила приходит от того, как хорошо ты используешь эти инструменты.

    8. Combat & Environment¶

    Боевая система¶

    • Tick-rate: 30 TPS (серверная симуляция, НЕ в реальном времени)
    • Batch simulation: Вся комната симулируется мгновенно (~100ms), результат отдаётся целиком
    • Хитбоксы: Коллизии через physics shapes (круги, капсулы)
    • Снаряды: Серверные, с проверкой попадания на каждом тике
    • Статус-эффекты: Burn (DoT), Freeze (slow), Poison (DoT + heal reduction), Stun (no action)
    • Детерминизм: Фиксированный seed рандома → одинаковый результат при одинаковых входных данных

    Типы комнат¶

    Тип Описание
    Combat Стандартный бой, 1-3 волны мобов
    Elite Один мощный элитный враг + мобы
    Boss Босс с фазами и механиками
    Treasure Без врагов, повышенный лут
    Challenge Особые условия (таймер, no-hit, ограничения)

    Интерактивные объекты¶

    Объект Поведение AI-взаимодействие
    Каверы (стены, бочки) Блокируют снаряды, разрушаемые AI может использовать Take Cover
    Разрушаемые (ящики, горшки) Ломаются от урона, могут дропнуть лут AI автоматически ломает при контакте
    Толкаемые (бочки, блоки) Физика, можно двигать AI может толкать для создания барьеров
    Ловушки (шипы, лава, турели) Наносят урон при контакте/в зоне AI уклоняется через глобальный AI
    Двери Открываются после зачистки комнаты Авто-переход

    Локации (биомы)¶

    Биом Тематика Особенности
    Sewers Канализация, стартовый Узкие коридоры, мало каверов
    Catacombs Подземелье, кости Ловушки, тёмные зоны
    Library Заброшенная библиотека Разрушаемые полки, магические враги
    Forge Кузница, лава Лавовые зоны, огненные враги
    Throne Финальный Открытые арены, сложные боссы

    9. Balance System (PvP-Ready)¶

    Принципы баланса¶

    1. Нет инфляции чисел — HP и урон растут линейно, не экспоненциально
    2. Всё относительно — урон выражается в % от базового, не в абсолютных числах
    3. Time-to-Kill (TTK) — основная метрика баланса
    4. PvP-ready — те же формулы работают для PvP без перебалансировки

    Базовые статы¶

    Стат Описание Базовое значение
    max_hp Максимальное здоровье 100
    base_damage Базовый урон 10
    armor Снижение физ. урона (%) 0
    resistance Снижение маг. урона (%) 0
    speed Скорость передвижения (px/s) 200
    attack_speed Атак в секунду 1.0
    crit_chance Шанс крита (%) 5
    crit_damage Множитель крита 1.5x

    Формула урона¶

    raw_damage = base_damage * skill_multiplier * (1 + bonus_damage%)
mitigation = armor% (for physical) or resistance% (for magical)
final_damage = raw_damage * (1 - mitigation / 100)

// Крит
if (random < crit_chance):
    final_damage *= crit_damage

    Формула брони/сопротивления (diminishing returns)¶

    effective_mitigation% = armor / (armor + K)

    Где K — константа = 100. Это даёт: - 0 armor → 0% mitigation - 50 armor → 33% mitigation - 100 armor → 50% mitigation - 200 armor → 67% mitigation - 500 armor → 83% mitigation

    Никогда не достигает 100%. Работает одинаково для PvE и PvP.

    TTK таблица (цель для баланса)¶

    Сценарий Target TTK
    Player vs Normal mob 2-4 секунды
    Player vs Elite mob 8-15 секунд
    Player vs Boss 60-120 секунд
    Player vs Player (PvP) 5-10 секунд
    Mob vs Player (no armor) 8-12 секунд

    Масштабирование по этажам подземелья¶

    enemy_hp = base_hp * (1 + floor * 0.1)
enemy_damage = base_damage * (1 + floor * 0.08)

    Пример (этаж 10): - Моб HP: 100 * (1 + 10 * 0.1) = 200 HP - Моб урон: 10 * (1 + 10 * 0.08) = 18 damage

    Рост линейный, не экспоненциальный. На этаже 50 моб имеет 600 HP, не 1,500,000,000.

    Скилл-множители¶

    Тип скилла Multiplier Cooldown Пример
    Быстрая атака 0.8x 0.3s Jab
    Обычная атака 1.0x 0.8s Slash
    Сильная атака 1.5x 2.0s Heavy Strike
    AoE 0.6x (per target) 3.0s Whirlwind
    Heal 0.5x (as heal) 4.0s Mend
    Ultimate 3.0x 15.0s Meteor

    10. Playback & Replay System¶

    Ключевой инсайт: бой = предзаписанное видео¶

    Поскольку игрок НЕ отправляет input во время боя, сервер может просимулировать всю комнату мгновенно и отдать результат целиком. Клиент — это видеоплеер, а не игровой клиент.

    Как это работает¶

    1. Клиент отправляет: блюпринты + экипировку + скиллы
2. Сервер за ~100ms симулирует всю комнату (1800 тиков = 60 сек боя)
3. Сервер возвращает: массив snapshots + лут + результат
4. Клиент проигрывает snapshots как видео

    Управление воспроизведением¶

    Действие Описание
    Play/Pause Запуск/пауза воспроизведения
    Fast Forward x2, x4, x8 скорость
    Slow Motion x0.5, x0.25 скорость
    Rewind Перемотка назад (просто seek по массиву snapshots)
    Timeline Scrub bar по всему забегу
    Room Jump Быстрый переход между комнатами
    Camera Свободная камера, привязка к персонажу
    Skip Пропустить комнату (результат уже известен)

    Техническая реализация¶

    • Сервер генерирует массив SimulationResult { snapshots[], loot[], outcome }
    • Каждый snapshot: позиции сущностей, HP, действия, события
    • Формат: protobuf, сжатие delta (каждый snapshot = diff от предыдущего)
    • Размер: ~0.5-2 MB на комнату (30 TPS * ~60 сек * delta compression)
    • Клиент хранит весь забег локально для пересмотра

    AI Debug Overlay¶

    • Какой модуль активен (подсветка)
    • Какой нод блюпринта сейчас выполняется
    • Какую цель выбрал и почему
    • Decision tree visualization в реальном времени
    • Доступен и во время первого просмотра, и при replay

    11. Multiplayer & Network Architecture¶

    Модель¶

    • Co-op: 1-4 игрока в одном подземелье
    • Авторитетный сервер: Вся симуляция на сервере, batch mode
    • Каждый сам за себя: Нет принудительных ролей, нет team UI
    • Помощь через блюпринты: Ничто не мешает написать модуль Healer с условием Ally HP Below 40%

    Сетевая модель (Batch Simulation)¶

    Phase 1 — LOBBY (WebSocket):
  Client → Server: подключение, выбор/создание комнаты

Phase 2 — UPLOAD (HTTP POST или WS message):
  Client → Server: блюпринты + экипировка + скиллы всех игроков
  Server: ждёт пока все игроки отправят свои билды

Phase 3 — SIMULATE (серверная сторона, ~100ms):
  Server: batch simulation всей комнаты
  - Загружает блюпринты всех игроков
  - Генерирует комнату (враги, объекты, layout) из seed
  - Прогоняет N тиков до конца боя
  - Собирает: snapshots[], loot per player, outcome

Phase 4 — DELIVER (один ответ):
  Server → Client: SimulationResult (весь бой целиком)
  Client: проигрывает как видео

Phase 5 — NEXT ROOM:
  Repeat от Phase 2

    Что это даёт¶

    Проблема классики Наше решение
    Client prediction Не нужно — нет input
    Rollback netcode Не нужно — нет input
    Input delay / lag compensation Не нужно — нет input
    Snapshot interpolation Не нужно — все кадры уже есть
    Desync Невозможен — один сервер, один результат, все видят одно и то же
    Cheating (speed hack, aimbot) Невозможен — клиент ничего не контролирует

    Протокол¶

    По сути REST-like поверх WebSocket: - UploadBuild → клиент шлёт свой билд - SimulateRoom → сервер симулирует и возвращает результат - NextRoom / EndRun → управление забегом - WebSocket нужен только для lobby sync (все готовы → старт)

    Лут¶

    • Лут индивидуальный (каждый видит и получает свой)
    • Лут генерируется сервером в момент симуляции
    • Нет trade между игроками (MVP)

    12. Будущее PvP¶

    Арена¶

    Те же персонажи, те же блюпринты, те же формулы. Два игрока (или две команды) ставят своих AI друг против друга.

    Почему это работает¶

    • Баланс PvP-ready с самого начала (diminishing returns, линейный рост)
    • Нет прямого контроля — PvP это соревнование "чей код лучше"
    • Мета не даёт прямой силы, только инструменты
    • Одинаковые формулы для PvE и PvP
